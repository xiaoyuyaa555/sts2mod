# HextechRunes v0.99.1 API notes

Purpose: record APIs and local facts already confirmed during v0.99.1-lite work so future debugging does not repeat broad source/API scans.

Last updated: 2026-06-29.

## Local build facts

- Hextech source: `D:\users\code\sts2mod-main\_git_pr\sts2mod\hextech-runes\core`.
- v0.99.1 game refs: `D:\users\code\sts2mod-main\海克斯符文\本体\versioned-dll-backups\0.99.1\game-refs`.

- A direct `dotnet build` with the wrong refs path can produce global `MegaCrit`/`Godot` missing errors. Treat those as environment/path errors, not rune-specific API failures.

## Manifest / deterministic test config facts

- v0.99.1 manifest does not support `min_game_version`.
- v0.99.1-compatible manifest fields are `id`, `name`, `author`, `description`, `version`, `has_pck`, `has_dll`, `dependencies`, `affects_gameplay`.
- Deterministic test config path is the Godot user path: `%USERPROFILE%\AppData\Roaming\SlayTheSpire2\HextechRunes\test_config.json`.
- Test config rune IDs are `ModelId.Entry` values, not category-prefixed IDs. Use `ADAMANT_RUNE`, not `RELIC.ADAMANT_RUNE`.

## STS2MCP v0.99.1 facts

- Confirmed working root: `GET http://localhost:15526/`.
- Confirmed state endpoint: `GET http://localhost:15526/api/v1/singleplayer`.
- Local STS2MCP has test-only `POST /api/v1/singleplayer` action `test_start_run` / `test_start_singleplayer_run` with `test_only=true`.
- `test_start_run` can pass `hextech_rarity` as `silver`, `gold`, or `prismatic` to start a rarity-pinned custom run.
- For custom rarity start, the MCP-created `ModifierModel` must be `ToMutable()` before passing it to `NGame.StartNewSingleplayerRun`; otherwise the run can get stuck at `state_type=unknown` / floor 0.

## Player rune registry / ID facts

- Player rune registration starts from `HextechPlayerRuneRegistry.Registrations`.
- Deterministic override resolves configured IDs against `ModelDb.GetId(runeType).Entry`.
- Runtime availability filter is `HextechRuntimeRuneCompatibility.IsPlayerRuneAvailableForCurrentRuntime(Type runeType)`.
- Compile-time excluded v0.99.1 runes remain excluded with `#if !STS2_99_1 && !STS2_100_0`; do not restore them through runtime config.
