## Runtime-disabled mechanism

`HextechRuntimeRuneCompatibility.IsPlayerRuneAvailableForCurrentRuntime(Type runeType)` currently filters only types recorded through `MarkPlayerRuneHookFailed<TRune>()`.

That means a rune can become unavailable during a run if its hook installation fails on the current game version/runtime. This is dynamic state, not a static registry exclusion.

### Manual tier pinning (skip rarity roll)

Preferred manual setup when `test_config.json` forced IDs miss due to rolled tier mismatch:

1. Singleplayer → **Custom** (not Standard).
2. Check **only one** of Silver / Gold / Prismatic Hextech tier options.
3. Start run → skip first relic → **Continue** → Hextech selection opens at the pinned tier.

Full steps: `docs/v0.99.1-automation-smoke-test.md` § **Manual custom mode**.

Harness note: forced rune IDs must be `ModelId.Entry` values such as `SOUL_EATER_RUNE`, not category-prefixed strings such as `RELIC.SOUL_EATER_RUNE`. Combine **custom tier** + `test_config.json` for fastest manual iteration.
## Multiplayer follow-up: JeweledGauntlet power-card replay

Recorded: 2026-06-30.

Observed in LAN multiplayer logs: host detected `State divergence` immediately after remote player `1000` played `CARD.FASTEN`. User confirmed the remote player played a Power/ability card and triggered `JeweledGauntletRune`.

Current temporary mitigation in `src/Runes/JeweledGauntletRune.cs`:

- Singleplayer behavior unchanged.
- LAN multiplayer attacks/skills still use existing replay logic.
- LAN multiplayer `CardType.Power` replay is skipped to avoid checksum divergence.

This is a stopgap, not the desired final design. Preferred future repair is non-disabling:

1. Replace the mutable `ConsumeCombatProcOrdinal(...)` replay-roll key with a stable card-play identity shared by host/client, ideally including run seed, player NetId, combat/floor, round, card instance identity, target identity, and if available the LAN `PlayCardAction` id.
2. If a stable identity is not sufficient, upgrade to host-authoritative replay decision: host rolls once and synchronizes `shouldReplay` to clients.
3. Longer-term option: move Jeweled Gauntlet replay into a synchronized Hextech/LAN `GameAction` instead of only returning `playCount + 1` inside `ModifyCardPlayCount`.

Do not treat the current Power-card skip as the final compatibility solution. Re-test with both players using the same local package before restoring multiplayer Power-card replay.
