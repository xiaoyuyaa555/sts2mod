## Manual custom mode: force Silver / Gold / Prismatic pool (no rarity roll)

This is the preferred **manual** way to test a specific rarity without waiting for the act roll or fighting `[HextechTestMode] not-in-current-filtered-pool` when `test_config.json` forces a rune whose registry rarity does not match the rolled tier.

Last verified: 2026-06-28 (STS2 **0.99.1**, user deep-test session).

### Steps

1. Start **singleplayer** and choose **Custom** (自定义), not Standard (标准).
2. In custom run setup, find the Hextech tier options (**Silver / Gold / Prismatic** — 白银局 / 黄金局 / 棱彩局).
3. Enable **only** the tier you want to test; leave the other tiers **unchecked**.
   - Example: test `SOUL_EATER_RUNE` (Gold) → check Gold only.
   - Example: test `CARD_INSPECTION_RUNE` (Prismatic) → check Prismatic only.
4. Start the run. The game skips the usual first-relic pick — click **Continue** (继续).
5. You land directly on **Hextech rune selection** with candidates from the forced tier pool.

### Why this helps

| Problem with `test_config.json` alone | Custom mode fix |
| --- | --- |
| Act rarity is rolled randomly (Silver / Gold / Prismatic). | Custom setup pins the tier before the run starts. |
| Forced offer IDs are filtered by the rolled tier; mismatches log `not-in-current-filtered-pool`. | Matching tier → target rune stays in pool without rerolling acts. |
| Prismatic tests may require many restarts. | Check Prismatic only → first Hextech screen is Prismatic. |

`test_config.json` remains useful to **pin specific rune IDs** into the 3-offer list once the tier is correct. Combine both: custom tier + forced offers for fastest iteration.

## Single-rune selection smoke flow

1. Write deterministic config with the target rune as the first forced offer.
2. Start/restart the game.
3. Wait for STS2MCP:

```powershell
Invoke-RestMethod http://localhost:15526/
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer
```

4. Start a run:

```powershell
$body = @{ action='test_start_run'; test_only=$true; seed='CODEXTEST99'; ascension_level=0 } | ConvertTo-Json -Compress
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer -Method Post -ContentType 'application/json' -Body $body
```

5. Choose Neow option 0, then continue:

```powershell
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer -Method Post -ContentType 'application/json' -Body '{"action":"choose_event_option","index":0}'
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer -Method Post -ContentType 'application/json' -Body '{"action":"choose_event_option","index":0}'
```

6. Assert the state is `overlay` / `HextechRuneSelectionScreen`.
7. Read Hextech options:

```powershell
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer -Method Post -ContentType 'application/json' -Body '{"action":"hextech_get_rune_selection"}'
```

8. Select the target option:

```powershell
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer -Method Post -ContentType 'application/json' -Body '{"action":"hextech_select_rune","index":0}'
```

9. Scan logs for:

- `MissingMethodException`
- `MissingFieldException`
- `TypeLoadException`
- `Harmony patch failure`
- `FileNotFoundException`
- `[HextechTestMode] WARN`

Known test harness caveat: forced player rune offers are filtered by the current randomly rolled rarity. If the current selection rarity does not match the forced rune rarity, `[HextechTestMode]` logs `not-in-current-filtered-pool` and falls back/fills from the normal pool. **Use custom mode tier pinning** (above) to avoid this during manual deep tests.

### `HUNDRED_REFINEMENTS_RUNE` counter note

The relic counter shows `_bodyForgeCount % 3` (values **1**, **2**, then **0** when the forge payout fires). A single body forge showing **+1** is expected; the random attribute forge appears on the **3rd** body forge, not the 1st.

## MCP custom-rarity start action

Last verified: 2026-06-28 (STS2 **0.99.1**).

STS2MCP test-only `test_start_run` now supports a Hextech custom-run rarity modifier directly from the main menu:

```powershell
$body = @{
  action = 'test_start_run'
  test_only = $true
  seed = 'CODEXCUSTOMGOLD'
  ascension_level = 0
  hextech_rarity = 'gold'
} | ConvertTo-Json -Compress
Invoke-RestMethod http://localhost:15526/api/v1/singleplayer -Method Post -ContentType 'application/json' -Body $body
```

Supported values: `silver`, `gold`, `prismatic`.

Verified response includes:

```json
{
  "status": "ok",
  "hextech_rarity": "gold",
  "hextech_modifier": "HEXTECH_GOLD_RUN_MODIFIER",
  "should_save": true
}
```

Implementation note for future MCP edits: resolve the Hextech modifier type from loaded assemblies and pass `ModelDb.GetById<ModifierModel>(id).ToMutable()` into `NGame.StartNewSingleplayerRun`. Passing the ModelDb prototype directly was observed to leave the run at `state_type=unknown` / floor 0 with no local player.

Validation result: `hextech_rarity='gold'` + `test_config.json` forcing `HUNDRED_REFINEMENTS_RUNE` produced Gold candidates with `HUNDRED_REFINEMENTS_RUNE` at index 0; selecting it reached `state_type=map` with the relic owned.
